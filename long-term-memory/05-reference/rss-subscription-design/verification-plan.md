# RSS 验证、发布与回退

> 主入口：[设计方案](README.md)。状态：实施阶段验收计划，**不是已通过的测试清单**。
> 本次已执行的只读实验见[证据文档](compatibility-and-evidence.md#7-已执行的只读验证)。
> 后续实施已完成的验证和仍未验证的项目见[实施记录](implementation.md)；本表继续作为回归验收计划，不整体标为全部通过。

## 1. 放行原则

需要四层证据：精确版本契约测试、全站 clean build、真实浏览器入口验收、获授权后的双目标部署验证。前一层不能替代后一层。

本地 RSS 失败时阻止本次发布，不删除或改动线上已有站点。现有 webp 的删图/改引用行为不在 RSS 校验的可逆保证内，验证阶段不使用 opt/pub。

## 2. 单元与契约测试

使用 Node 内置测试运行器；共享策略是纯函数，不调用扫描器、不需要完整 Hexo.init/load。测试必须在当前 Hexo7/Warehouse5 与精确 feed4 依赖下执行真实序列化，不能把本次捕获桩实验当正式放行。

| 编号 | 用例 | 预期 |
| --- | --- | --- |
| T01 | 公开 `_posts` 文档 | 两种格式均收录 |
| T02 | `_drafts`，同时打开 render_drafts | 排除 |
| T03 | `_posts` 内 published:false | 排除 |
| T04 | draft:true、feed:false | 排除 |
| T05 | private/hidden/hide true、非空 password | 排除；日志不含敏感值 |
| T06 | coffer、游戏、图库、生日 Page 假混入数据 | 不收录 |
| T07 | 名含“连连看”的普通公开文章 | 正常收录，不做标题黑名单 |
| T08 | future:true 下的未来文章 | RSS 仍排除，到期后下一次构建才进入 |
| T09 | 路径穿越、绝对磁盘路径、缺 source | 拒绝，不靠字符串包含判断 |
| T10 | `feed: "false"` 等字段类型错误 | 明确失败 |
| T11 | 35 篇合格、夹杂若干不合格文章 | 先筛选后取最近 30 |
| T12 | top/swiper_index 不同、相同日期文章 | 发布日期主序，source 稳定次序 |
| T13 | 筛选/摘要清理后检查原模型 | locals、posts、日期、正文、首页排序未被适配修改 |
| T14 | 中文、emoji、`& < > \"`、XML 禁止控制字符 | 字符完整、正确转义、XML 可解析 |
| T15 | 超长 description | Unicode 安全截断；无未闭合 HTML |
| T16 | 缺 description 且正文有 script/敏感代码示例 | “阅读全文”降级，不复制正文 |
| T17 | 路径含中文、空格、已有百分号编码 | permalink 与主站一致，不重复编码 |
| T18 | content:false | 不含正文 script/style/iframe、代码高亮表格或有效全文内容 |
| T19 | 同一文章两种格式 | Atom id 与 RSS guid 一致，链接与原发布日期一致 |
| T20 | 修改窗口内旧文，最新发表文章不变 | 条目 ID 不变；顶层 updated/lastBuildDate 反映窗口内最大值 |
| T21 | 无改动重复生成 | 同年份、同输入下语义稳定；不使用构建 now 更新文章时间 |
| T22 | 仅改变文件 mtime | 验证并记录默认自动时间策略的影响，不伪装成跨机器稳定 |
| T23 | 空集合 | 当前生产配置下报错阻止发布；不能静默产空/缺失文件 |
| T24 | 插件缺失、版本不符、函数路径不存在 | 非零退出，不回退无筛选入口 |
| T25 | 本地适配脚本缺失/语法错误，官方入口仍关闭 | postbuild 检测无有效双 feed 并阻断 |
| T26 | 两条输出路径相同、source 同名 XML | 拒绝冲突 |
| T27 | 顶层时间修正后的 XML | namespaces、中文、转义、category、link、summary 均保真 |
| T28 | Atom/RSS 边界语义 | Atom author/updated/self；RSS channel 必填字段、guid、pubDate 均满足协议；不能只判断 XML 语法 |

时间 fixture 必须有显式时区，并允许注入固定 now；不以电脑真实日期决定测试成败。

默认空集合处理采用“报错”是因为当前博客确定有公开文章且入口将始终展示。未来若需要空站模式，应成对设计空 feed 与入口隐藏，不能只关闭校验。

## 3. 生成内校验

生成器持有筛选后的预期快照，应在返回路由前完成：

- 两种格式 XML 严格可解析，禁止 DTD 和外部实体；长度合理、编码正确。
- ID 集合与预期公开快照完全一致，数量等于 `min(合格文章数,30)`，顺序相同且唯一。
- 标题、摘要、日期、分类标签与投影一致，禁止出现非预期正文。
- 条目、self、图标的 URL 均正确；条目必须同源且与筛选快照中的 `post.path/permalink` 一致。此阶段其他生成器路由尚未全部刷新，不调用 `route.get` 假定文章已落盘，目标文件存在性留给 postbuild。
- 顶层时间修正只影响指定节点，不能误改条目 updated/pubDate。
- 所有错误抛出，不能用返回空 feed 掩盖错误。

这里是“只含公开内容”的主要证据，不能单凭输出里没有 `/coffer/` 字符串宣称无隐私泄漏。

## 4. 落盘校验 CLI

`tools/check-feed.js` 在 npm postbuild 中执行：

1. 结构化读取配置，确认功能启用时第三方默认入口关闭、两个路径唯一且符合约定。
2. 检查磁盘上两个 XML 都存在、非空、可解析，格式及必填字段正确。
3. 检查二者 ID/顺序/条数一致，无重复、无未来日期、无无效时间。
4. 检查主站 URL、self、文章链接及映射到 `public/` 的文章文件存在。
5. 检查标题/摘要、合理大小、不含全文脚本，以及禁用目录链接。
6. 检查首页/归档/代表文章各有且仅有两条正确自动发现声明。
7. 失败时返回非零退出码，输出 `[RSS]` 中文错误与可定位文件，不输出私密内容。

该 CLI 不应重新 Hexo.load，不重新运行 webp、coffer/生日扫描器，也不从线上抓取私密文件。

防陈旧说明：标准 pub 在 build 前执行 clean，避免旧 XML 掩盖生成器缺失。独立运行 `check:feed` 只能证明现存产物，不自动证明它与当前源文件完全同步；`hexo deploy` 也不能绕过此事实。

如要让 `npm run deploy` 同样强制检查，可另加 `predeploy`；它不会自动保护 pub 中直接调用的 `hexo deploy`，所以不能拿 predeploy 替代 postbuild。本期标准入口仍明确为 pub。

## 5. 真实本地构建

实施获批后，按仓库规则依次执行 `npm run clean`、`npm run build`，不为 RSS 验证运行 webp/opt/pub。

- 保存改动前的目标文件 diff 与用户文章状态，不还原用户工作。
- 首先验证现有 prebuild 的 MarkdownPreview 构建仍运行。
- 检查只新增预期 RSS 产物与入口，不改变公开文章 URL、首页置顶规则、目录折叠、轮播或公式正文。
- 检查 git status；coffer/生日生成 JSON 的变化要解释、保留，不自动 reset。
- 在隔离 fixture 中演练“新增文章 -> 重建”“修改摘要 -> 重建”“feed:false -> 重建”“删除文章 -> 重建”，不为测试擅删真实文章。
- 比较连续两次无内容变化构建的订阅语义；跨年 copyright 单列。
- 代表文章包括中文路径、长篇公式、内嵌 HTML、置顶旧文；最近 30 篇以实际数据重算，不硬编码当前文章列表。

订阅条目删除不会强制删除读者本地缓存。测试报告必须把“生成源已移除”和“客户端数据已撤回”区分开。

## 6. ego-browser 验收

先读 [ego-browser 验证指南](../../03-api-practices/ego-browser-verification.md) 与当时实际安装的 ego-browser skill；若指南中的旧 API 与 skill 不一致，以当前 skill 为准。

使用一个任务空间、复用页面，预览端口占用时换端口，不影响用户已有服务：

- 桌面与 390px 移动断点检查首页社交区、作者卡图标布局，无横向溢出和重叠。
- RSS 图标使用已有 Font Awesome，悬停标题和链接地址正确，点击访问 XML，不被当作文章页。
- DOM 检查首页、归档、代表文章的两个 `<link rel="alternate">` 及 MIME；即使正文包含 MIME 示例也不缺失。
- HTTP 读取两个本地 XML，确认 200 且不是 HTML 错误页。
- 独立自定义页面无 RSS 入口不算失败；不为验收尝试解锁或读取私密内容。
- 按未来启用 PJAX 的情形单列验证需求，不在此次顺手开启它。
- 最好用至少一种实际阅读器导入本地测试可达地址或获授权的公开地址，确认摘要、中文、时间、图标及去重表现。阅读器尚未测时明确记录，不能由 DOMParser 成功推出可用性。

只读浏览器访问发布后的订阅文件不需要把整个 feed 上传到第三方在线验证器；优先本地解析，以免无意向外部服务额外传送内容。

## 7. 获授权后的发布

运行 pub 前重新确认授权、工作区变化、WebP 会删除源图的既有风险，以及两个部署目标。RSS 没有取消原发布链的任何副作用。

两个目标均需验证：

- 日志和部署结果分别成功；第一个失败可能阻止第二个，不得只看最后一行或只测主域名。
- `/atom.xml`、`/rss.xml` 返回 200 和实际 XML，不是登录页、404 fallback、301 循环或缓存的 HTML。
- Content-Type 应是相应 feed MIME 或正确 XML 类型；若主机返回 HTML 类型，应在托管配置层修正，不伪造源文件。
- 主站 canonical 域名、self 和文章 ID 保持一致；镜像提供同一套静态 XML，不根据访问 host 改写 ID。
- 比较条目集合/摘要/时间与本地结果，考虑 CDN 缓存；不能只看 HTTP Last-Modified 判定内容同步。
- ETag/Last-Modified/Cache-Control 由托管端决定，Hexo XML 本身不能承诺它们；持续命中旧缓存时针对 XML 配置缓存策略。
- 确认最新公开文章已在窗口内，确认不收录页面路径；不在日志打印私密记录。

阅读器有自己的刷新周期和缓存，“pub 完成”意味着服务器 feed 更新，不意味着所有读者即时收到通知。没有定时重建就没有定时发布，即使某篇未来文章到期也要下一次构建才进入 feed。

## 8. 回退与将来升级

回退前先取得用户授权，仅撤销 RSS 自己的变更，保护无关文章与主题改动：

1. 停止标准发布，保存错误证据。
2. 成对关闭本地 RSS 开关、图标、head 声明及强制 postbuild 检查，避免出现“入口还在、文件没了”或永久阻断 build。
3. 按审阅后的逐文件补丁恢复依赖/配置，不使用 reset --hard、批量 checkout 或删除 node_modules。
4. 获准后 clean/build 检查；线上回退另需部署授权。

上线后订阅地址应尽量长期保留。由于公共接口已被读者保存，移除功能会产生订阅失效；是否保留最后一份 feed 或提供迁移说明，应单独确认。

未来升级时的回归清单：

- feed 插件：内部 generator 路径、enable 提前退出、默认字段、Query 方法、模板支持、时间和 XML 输出差异。
- Feedsmith：纯文本/HTML content 类型、命名空间和 lenient 行为；不直接改成 master 或未审核的新大版本。
- Hexo8/Warehouse6：Query 快照构造、published/draft、locals 缓存失效、生成器注册与调用。
- Butterfly：social 格式、inject.head、PJAX 排除和 DOM 位置；只迁移必要配置，不覆盖定制模板。
- Node/构建机器：引擎要求、时区、mtime、锁文件安装可重复性。

RSS 不能成为顺手升级整个博客的理由。任何版本升级都先保持现有 RSS 地址和条目 ID，并重复上述契约测试。
