# 04-operations — 操作记录与日志

本目录按时间顺序记录每次对博客项目的实质性修改。

---

## 日志编号规则

每条记录使用 `#N` 编号，从 1 开始递增。

## 记录格式

```markdown
### #N — YYYY-MM-DD — 操作简述

**操作人**：XBXyftx（或 AI 助手）
**涉及文件**：
- `文件路径1` — 做了什么
- `文件路径2` — 做了什么

**操作详情**：
详细描述做了什么、为什么做、遇到了什么问题、如何解决的。

**验证结果**：
- [ ] 本地预览正常
- [ ] 构建成功
- [ ] GitHub Pages 部署正常
- [ ] 私有服务器部署正常

**遗留问题**：
如有未解决的问题，在此记录。
```

---

## 为什么需要操作日志

1. **上下文压缩后恢复**：AI 会话触发上下文压缩后，可以通过日志快速恢复"我之前做了什么"
2. **跨会话延续**：过几天回来继续开发，通过日志快速找回当时的思路和未完成的任务
3. **问题回溯**：出现故障时，可以通过日志定位最近的改动
