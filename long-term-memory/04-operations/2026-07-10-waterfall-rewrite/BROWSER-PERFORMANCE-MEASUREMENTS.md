## 1. 测量目的与对照边界

本记录用于量化提交 `9988ac4` 的首页瀑布流重写，相对于优化前基线 `69772c8` 的变化。比较对象只限首页瀑布流相关实现，不将全站星空 Canvas、页脚计时器、第三方资源等其他持续任务错误归因给此次改动。

| 对照项 | 优化前基线 | 优化后实现 | 说明 |
| --- | --- | --- | --- |
| Git commit | `69772c847d46b251eafa028394b6f1ebef291b68` | `9988ac47bedde1380938f44b82dcde34aec80b6f` | 均存在于 `origin/master` 历史。 |
| 提交说明 | `docs: 记录渲染性能审计基线` | `perf: 重写首页响应式瀑布流` | 基线在任何瀑布流源码改动前创建。 |
| 首页 fixture | 15 张卡片、15 张封面图 | 15 张卡片、15 张封面图 | 自动布局断言在每轮测量中确认。 |
| 运行方式 | 对应提交独立生成的 `public/` 静态产物 | 对应提交独立生成的 `public/` 静态产物 | 由本地 HTTP 服务器分别提供，避免后续未提交公告配置或工作区内容污染 A/B。 |
| 浏览器 profile / 缓存 | 独立临时 profile、禁用 HTTP 缓存 | 相同 | 每次运行重新启动 Chrome。 |

### 5.3 最终移动端瀑布流专项观测值

以下计数由页面加载前注入的临时测量器获得，只匹配调用栈来自 `waterfall.js` 的行为；该测量器不属于生产代码，也不会写入生成网站产物。

| 场景 / 专项指标 | 优化前 `69772c8` | 优化后 `9988ac4` | 结论 |
| --- | ---: | ---: | --- |
| 空闲 15 秒：瀑布流 interval tick | 150 | 0 | 旧版约 10Hz 轮询已移除。 |
| 滚动 15 秒：瀑布流 interval tick | 150 | 0 | 滚动不再维持轮询。 |
| 滚动 15 秒：瀑布流 `cssText` 整体写入 | 14,352 | 0 | 旧版整批卡片覆写已移除。 |
| 滚动 15 秒：瀑布流 `console.*` 调用 | 81,643 | 0 | 旧版调试输出已移除。 |
| 两场景：由瀑布流创建的 `MutationObserver` | 0（采样窗口内无新建） | 0 | 源码静态对照已确认旧版有 1 个调试 observer、当前为 0；该 observer 在初始加载阶段创建，故不在本场景增量内重复计数。 |

按 15 秒滚动窗口线性换算，旧版约会发生 600 次轮询、57,408 次 `cssText` 整体写入、326,572 次调试调用 / 分钟；当前对应专项计数为 0。线性换算仅用于说明旧逻辑频率，不应用于预测其他设备的固定 CPU 百分比。

### 5.4 移动端结论与边界

可以确认：

1. 旧移动端 100ms 瀑布流轮询，以及滚动后的整批 `cssText` 样式覆写和调试输出，在当前实现的测量窗口内均为 0。
2. 在本机、此 Chrome 版本、此视口、三次中位数条件下，滚动期间 `ScriptDuration` 降低 85.3%；整页 `TaskDuration` 基本持平（-1.9%），因此不将聚合页面成本宣称为瀑布流的固定全页收益。
3. 当前移动端仍保持单列、卡片无重叠、分页位于列表后方。

不能仅凭此结果声称：所有访问者的 CPU 都降低固定比例、所有设备不会发热、所有 GPU 合成负荷改善，或整个首页的 Lighthouse / LCP 变化都由瀑布流改动造成。
