# Long-Term Memory Document Rules

> `long-term-memory/` 的文档维护规范。不要在每个功能文档中重复 Agent 调度规则；统一协议见 [agent.md](agent.md)。

## 1. 职责分层

- `MEMORY.md`：当前项目状态、全局导航、关键事实和任务入口；保持短小。
- `agent.md`：任务分类、渐进式读取、sub agent 路由、证据标签、停止条件和交接协议。
- `rules.md`：博客代码、内容、主题、构建、部署和安全边界。
- 分区 `README.md`：该分区的入口、文件地图和读取时机。
- 功能/操作/问题文档：单个主题的事实、证据、决策、验证和遗留事项。
- `04-operations/operation-log.md`：实质修改的时间线，不承载完整分析报告。

## 2. 入口与索引

- 每个主题保留一个主要入口；子文档通过入口链接，不在多个入口复制同一份长内容。
- 新增、移动、重命名、归档或改变状态时，同步父级 README 和 `MEMORY.md` 中必要的链接。
- 链接必须指向真实存在的文件或目录；删除/失效链接在完成前修复或明确标记为待确认。
- 根索引不记录完整日志、截图、原始用户描述或大段源码；这些内容下沉到对应分区。

## 3. 事实与状态

- 优先记录当前源码、配置、生成结果和可复现检查；旧文档和 commit 只能作为历史线索。
- 明确区分 `代码事实`、`生成事实`、`历史结论`、`用户/测试反馈`、`推断`、`待确认` 和 `已验证`。
- 不把静态检查写成构建成功，不把本地预览写成线上部署成功，不把用户未确认的方案写成验收结论。
- 状态使用事实性词语：`进行中`、`已实施`、`静态检查通过`、`待人工验证`、`待设备验证`、`无法验证：原因`。

## 4. 内容安全与脱敏

- 归档前移除密码、Token、SSH 信息、私有服务器细节、绝对本地路径和不必要的用户隐私。
- 只记录理解问题所需的最小源码片段；完整日志、截图和视频放在受控的证据位置。
- 私密文章系统的前端密码机制不得在长期记忆中被描述为真正的机密保护。

## 5. 审查清单

完成文档维护后检查：

- [ ] 入口、子文档和父级索引一致
- [ ] 链接和路径真实存在
- [ ] 当前事实与历史记录没有混写
- [ ] 验证结果和待确认事项分开
- [ ] 没有重复承载 Agent 调度逻辑
- [ ] 没有敏感信息、临时诊断或无关源码
- [ ] 文档长度适合渐进式读取
