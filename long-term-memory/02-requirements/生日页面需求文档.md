# 生日页面需求文档

## 核心思路

### 精神内核

从我这些年的事迹以及心路历程的变化，再加上我所取得的成就，来展现出我自身的蜕变，能力的成长以及心境上的变化。

> **当前定位补充（2026-05-07）**：页面不只是“个人勇敢历程”，顶部必须明确表达这是一份**给妈妈的生日礼物**。现行页面顶部标题为「给妈妈的生日礼物」，副标题为「把我的成长与感谢，慢慢讲给你听」。后续重构顶部区域时应保留这个礼物语境。

### 表现形式

整体以纵向的连续时间轴为主体，在屏幕正中间以一道流动的白色光带作为分割（像是白色的丝带挂在房顶向下自然垂下随风飘动的感觉随后从丝线的缝隙之间废除一些光点），每一条事件的文字呈左右左右的交替形式，在文字的对侧会放上一个数张图片或视频缩略图组成的相册堆叠图案，鼠标点击该堆叠相册会展开一个新的图层去显示其中所包含的图片和食品。然后右上角有一个叉子可以关掉。每一条滚动过去时，切换一次背景图片，背景图片做虚化处理。一次滚动所代表的是一整个事件页面，直接将当次的文字和图片相册切换为下一个，而并非是连续的滚动。同时每次滚动屏幕边缘所泛的光芒也会随之变化进行渐变。

## 实现细节

### 文案以及图片视频管理

对于每一个图片以及视频相册都要单独建一个子文件夹进行管理。在该子文件夹下会包含一个MD文件，文件中我会编写关于这次事件的概述。不想表达的话，最后你需要将MD渲染成统一的文字格式。这样以后我每次去新建事件的时候，就不需要直接修改HTML代码，而是在事件列表的文件夹下新建一个子文件夹，并在里头新建MD和放入图片还有视频。然后你在渲染的时候，要循环便利事件列表下的每一个子文件夹，去读取其中的MD文件以及图片、视频文件，制作成文字描述和图片视频相册。

### 性能优化

同时为了页面性能，还要去进行懒加载。图片相册在未点开时，不要加载完整的原图，而是仅加载缩略图，再点开相册，进入新的图层进行展示的时候，再逐一加载原图来减小服务器压力。

### 相册展示详情页

对于点击相册缩略图后展开的新图层页面，我们需要进行进一步的明确，如果其中包含视频，就要在视频的缩略图上放一个播放的按钮这个按钮可以使用SVG图片,点击后，将在该图层上新建一个视频播放器的图层进行播放，然后如果点击图片的话，就将图片以一个动画过渡，展开一个新的大图图层进行展示。这里还要注意其视觉风格要与主体页面一致，保持一种梦幻朦胧的美感。

### 主页面的滚动切换

所谓一次滚动代表一整页，指的是整屏切换，将事件的文字、相册、缩略还有背景的虚化图片作为一个整体单词滚动直接切换以上的3个组件。

### 异常情况处理

如果在进行加载时，遇到文件夹里头只有文字没有图片的情况，就是用流星效果背景作为替代。流星效果可以参考博客首页的流星的JS文件。

### 懒加载

对于懒加载，我们当前的博客框架中已经有了自定义的懒加载逻辑。请你优先复用现有的懒加载逻辑，如果与当前效果出入过大或者是无法应用的话，就请限制现有的那加载逻辑不会应用于当前页面随后在页面的代码中直接重写了加载逻辑，针对于这个页面进行优化。

## 附录 A：Hexo 框架约束与自定义系统注意事项（AI 必读）

### A.1 主题隔离策略

生日页面采用 **`layout: false`** front matter，彻底绕过 Butterfly 主题的 `layout.pug` 包装。这意味着：
- 主题不会注入 `additional-js.pug` 底部脚本（包括懒加载、监控、星空背景等）
- 主题不会注入 `head.pug` 中的全局 CSS
- 页面必须**完全自包含**：所有 CSS 内联、所有 JS 使用 IIFE 或外置独立文件
- 若未来需要修改页面结构或样式，**不要依赖主题的任何类名或 DOM 结构**

> 详细论证参见：[`05-reference/birthday-gift-page-design.md`](../05-reference/birthday-gift-page-design.md) 第一节「Hexo 框架限制深度分析」

### A.2 事件数据扫描机制

页面数据由 Hexo 脚本 [`scripts/birthday-gift-scanner.js`](../../scripts/birthday-gift-scanner.js) 自动生成：
- 注册时机：`hexo.extend.filter.register('before_generate', ...)` + `hexo.extend.generator.register('birthday-gift-data', ...)`
- 扫描路径：`source/birthday-gift/events/` 下的子文件夹
- Markdown 渲染：`hexo.render.renderSync({text, engine: 'markdown'})`
- 输出产物：`public/birthday-gift/events-data.json`

**修改此页面时若涉及数据格式变更，必须同步修改扫描器脚本。**

### A.3 全局懒加载系统的冲突规避

项目当前并存 **5+ 套懒加载实现**（详见 `03-api-practices/lazy-loading-system.md`）。其中 `scripts/image-dimensions.js` 会在 `after_render:html` 阶段给所有 `<img>` 注入 `loading="lazy"` + `width/height`，可能干扰生日页面的自定义懒加载逻辑。

**已采取的隔离措施**：
- `image-dimensions.js` 的 `EXCLUDE_PATH_PATTERNS` 中已添加 `/\/birthday-gift\//` 正则排除
- 生日页面使用独立的懒加载策略：切换事件时预加载缩略图，相册弹层打开后再加载原图

> 全局懒加载全貌参见：[`03-api-practices/lazy-loading-system.md`](../03-api-practices/lazy-loading-system.md)

### A.4 文件命名规范（强制）

事件文件夹内的媒体文件支持两种模式。

**模式 1：快速放图**  
直接放入普通图片文件即可被识别为相册媒体，例如 `01.jpg`、`02.webp`、`03.png`。适合用户快速补图。`bg`、`background`、`cover`、`poster` 等保留名图片不会被当作相册媒体。

**模式 2：精确命名**  
需要手动指定缩略图、原图和视频封面时，使用以下前缀约定：

| 前缀 | 用途 | 示例 |
|------|------|------|
| `thumb-*` | 相册堆叠缩略图 | `thumb-1.jpg` |
| `photo-*` | 原图（弹层展示） | `photo-1.jpg` |
| `video-*` | 视频文件 | `video-1.mp4` |
| `thumb-video-*` | 视频封面（可选） | `thumb-video-1.jpg` |

**序号对应规则**：`thumb-1.jpg` ↔ `photo-1.jpg`（同序号自动关联）。不按此命名会导致相册关联失败。

### A.5 背景图与边缘泛光

- 背景图通过 `background` front matter 字段指定，页面渲染时虚化处理
- 边缘泛光颜色通过 `glowColor` front matter 字段指定，格式 `"R, G, B"`，由 CSS 变量 `--glow-color` 动态切换
- 无图片/视频的事件自动启用 Canvas 流星效果（参考首页 `header-universe.js` 的粒子逻辑）
